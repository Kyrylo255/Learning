1. Створення репозиторію та перевірка стану
Команда	Що робить
git init	Створює локальний Git-репозиторій у поточній папці.
git status	Показує поточну гілку, змінені файли та стан комітів.
git status --short	Короткий варіант статусу репозиторію.
git log	Показує історію комітів.
git log --oneline	Показує кожен коміт в одному рядку.
git log --oneline --graph --all	Показує історію всіх гілок у вигляді графа.
git show	Показує інформацію про останній коміт і його зміни.
git show <commit>	Показує конкретний коміт за його хешем.

2. Додавання змін і створення комітів
Команда	Що робить
git add test.txt	Додає зміни конкретного файлу до підготовки коміту.
git add .	Додає зміни з поточної папки та її підпапок до підготовки коміту.
git commit -m "First commit"	Створює коміт із підготовлених змін і заданим повідомленням.
git diff	Показує зміни у файлах, які ще не додані через git add.
git diff --staged	Показує зміни, уже підготовлені до коміту.

3. Підключення до віддаленого репозиторію
Команда	Що робить
git clone <URL>	Копіює віддалений репозиторій на комп'ютер.
git remote -v	Показує віддалені репозиторії та їхні URL.
git remote add origin <URL>	Додає віддалений репозиторій під назвою origin.
git fetch origin	Завантажує нові дані з origin, не об'єднуючи їх автоматично з поточною гілкою.
git pull	Отримує зміни з віддаленого репозиторію та інтегрує їх у поточну гілку.
git push	Відправляє локальні коміти у віддалений репозиторій.
git push origin master	Відправляє локальну гілку master у віддалену гілку master на origin.
git push -u origin master	Відправляє гілку master і налаштовує її відстеження віддаленої гілки.
git push -u origin feature	Відправляє гілку feature та налаштовує відстеження origin/feature.
Запам'ятай різницю:
- fetch — отримати інформацію про нові коміти.
- pull — отримати й інтегрувати зміни.
- push — відправити свої коміти на сервер.

4. Робота з гілками (branches)
Команда	Що робить
git branch	Показує локальні гілки.
git branch -a	Показує локальні та віддалені гілки.
git branch -vv	Показує локальні гілки та інформацію про їхні відстежувані гілки.
git branch feature	Створює локальну гілку feature, але не перемикається на неї.
git switch master	Перемикається на гілку master.
git switch feature	Перемикається на гілку feature.
git switch -c feature	Створює гілку feature і відразу перемикається на неї.

5. Об'єднання гілок і конфлікти
Команда	Що робить
git merge feature	Об'єднує зміни з feature у поточну гілку.
git merge --abort	Перериває поточне злиття та намагається повернути стан до початку злиття.
git status	Допомагає знайти файли з конфліктами.
git add test.txt	Позначає конфлікт у файлі як вирішений після ручного виправлення.
git commit -m "Merge feature into master"	Завершує злиття, якщо Git очікує коміт після вирішення конфліктів.


Підключення до віддаленого репозиторію та клонування
mkdir projecthelper	Створити папку
cd projecthelper	Перейти в папку
git clone URL НазваПапки	Клонувати репозиторій
git remote -v	Переглянути адреси віддалених репозиторіїв
git fetch origin	Оновити інформацію про віддалені гілки
git branch	Показати локальні гілки
git branch -a	Показати локальні та віддалені гілки
git switch --track origin/feature	Створити локальну гілку з віддаленої
code .	Відкрити поточну папку у VS Code

на іншому користувачу треба прив'язати локальну гілку до віддаленої
